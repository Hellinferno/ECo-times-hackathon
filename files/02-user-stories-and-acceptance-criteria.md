# 02 — User Stories & Acceptance Criteria

## AlphaHunter AI — Opportunity & Decision Engine

---

## 1. Overview

This document defines all user stories and their acceptance criteria for AlphaHunter AI. Stories are organized by user role and feature area. Each story includes priority, effort estimate, and measurable acceptance criteria.

---

## 2. User Roles

| Role | Description |
|------|-------------|
| **Retail Investor** | Primary user; limited financial knowledge; seeks actionable guidance |
| **Power User** | Experienced trader; wants customization and deeper signal control |
| **Admin** | Internal operator; monitors system health and data pipelines |

---

## 3. Epic Structure

```
Epic 1 — Market Scanning
Epic 2 — Signal Detection & Explanation
Epic 3 — Backtesting & Validation
Epic 4 — Decision Engine & Trade Output
Epic 5 — Audit Trail & Replay
Epic 6 — Portfolio & Watchlist Management
Epic 7 — Notifications & Alerts
Epic 8 — Admin & System Monitoring
```

## 4. Epic 1 — Market Scanning

### US-101: Scan All NSE Stocks

> **As a** retail investor,  
> **I want** the system to automatically scan 100+ NSE stocks,  
> **So that** I don't have to manually track individual stocks.

**Acceptance Criteria:**
- [ ] System scans minimum 100 NSE-listed stocks per scan cycle
- [ ] Scan completes within 60 seconds
- [ ] Results display count of stocks scanned and opportunities found
- [ ] Scan timestamp is shown on the UI
- [ ] Stocks with no signals are excluded from results

**Priority:** P0 | **Effort:** L

---

### US-102: View Opportunity List

> **As a** retail investor,  
> **I want** to see a ranked list of current opportunities,  
> **So that** I can quickly identify the best stocks to act on.

**Acceptance Criteria:**
- [ ] List shows 5–15 opportunities ranked by confidence score
- [ ] Each item shows: stock symbol, signal type, confidence %, action (BUY/WATCH/AVOID)
- [ ] List refreshes on demand via "Scan Market" button
- [ ] Empty state shown if no opportunities detected
- [ ] Loading state shown during scan

**Priority:** P0 | **Effort:** M

---

### US-103: Filter Opportunities

> **As a** power user,  
> **I want** to filter opportunities by signal type or action,  
> **So that** I can focus on specific patterns I trust.

**Acceptance Criteria:**
- [ ] Filter options: BUY / WATCH / AVOID
- [ ] Filter options: Breakout / Volume Spike / Bulk Deal
- [ ] Filters apply instantly without re-scan
- [ ] Active filters are visually highlighted
- [ ] "Clear filters" resets to full list

**Priority:** P1 | **Effort:** S

---

## 5. Epic 2 — Signal Detection & Explanation

### US-201: View Signal Details

> **As a** retail investor,  
> **I want** to see what signals were triggered for a stock,  
> **So that** I understand why the system flagged it.

**Acceptance Criteria:**
- [ ] Shows all triggered signals: Breakout, Volume Spike, Bulk Deal
- [ ] Each signal includes the data behind it (e.g., "Volume 2.3x 20-day avg")
- [ ] Signals are shown with green/yellow/red indicator by strength
- [ ] UI loads within 2 seconds of stock selection

**Priority:** P0 | **Effort:** M

---

### US-202: Read AI Reasoning Explanation

> **As a** retail investor,  
> **I want** to read a plain-English explanation of why a stock is flagged,  
> **So that** I can understand the opportunity without needing financial expertise.

**Acceptance Criteria:**
- [ ] Explanation is generated by LLM and references actual data values
- [ ] Every sentence maps to a specific data point (price level, volume ratio, etc.)
- [ ] Explanation is 3–5 sentences maximum
- [ ] No generic phrases like "looks bullish" without data backing
- [ ] Explanation regenerates if data is refreshed

**Priority:** P0 | **Effort:** M

---

### US-203: View Breakout Signal Details

> **As a** retail investor,  
> **I want** to see the resistance level a stock broke through,  
> **So that** I can verify the breakout claim visually.

**Acceptance Criteria:**
- [ ] System shows the resistance level (e.g., ₹1,500 — 30-day high)
- [ ] Current price vs resistance is displayed
- [ ] % above resistance is calculated and shown
- [ ] Chart highlights the breakout level

**Priority:** P1 | **Effort:** M

---

### US-204: View Volume Spike Details

> **As a** retail investor,  
> **I want** to see how unusual the volume is compared to normal,  
> **So that** I can assess buying pressure myself.

**Acceptance Criteria:**
- [ ] Today's volume vs 20-day average volume shown
- [ ] Volume ratio displayed (e.g., "2.3x average")
- [ ] Volume bar chart shows last 10 days
- [ ] Spike day is highlighted on the chart

**Priority:** P1 | **Effort:** M

---

### US-205: View Bulk Deal / Institutional Signal

> **As a** power user,  
> **I want** to see if institutional investors made bulk deals,  
> **So that** I can follow smart money.

**Acceptance Criteria:**
- [ ] Bulk deal data fetched from NSE/BSE public feeds
- [ ] Shows: buyer name, quantity, price, date
- [ ] Flag shown if bulk deal occurred within last 5 trading days
- [ ] Signal absent if no recent bulk deals

**Priority:** P1 | **Effort:** L

---

## 6. Epic 3 — Backtesting & Validation

### US-301: View Backtest Results

> **As a** retail investor,  
> **I want** to see how similar signals performed historically,  
> **So that** I can trust the system's recommendation.

**Acceptance Criteria:**
- [ ] System finds last 5 occurrences of same signal pattern
- [ ] Shows success rate (e.g., "4/5 profitable")
- [ ] Shows average return (e.g., "+5.2% in 5 days")
- [ ] Shows worst case (e.g., "-3.1%")
- [ ] Historical cases listed with dates

**Priority:** P0 | **Effort:** L

---

### US-302: Understand Backtest Methodology

> **As a** power user,  
> **I want** to understand how the backtest was conducted,  
> **So that** I can assess its reliability.

**Acceptance Criteria:**
- [ ] "How was this calculated?" tooltip/modal is available
- [ ] Methodology describes: lookback period, matching criteria, measurement window
- [ ] Data source cited (e.g., "Based on 2-year historical price data via yfinance")
- [ ] Limitations stated (e.g., "Past performance does not guarantee future results")

**Priority:** P2 | **Effort:** S

---

### US-303: See Backtest on Chart

> **As a** power user,  
> **I want** to see past signal occurrences marked on the price chart,  
> **So that** I can visually confirm the backtest claims.

**Acceptance Criteria:**
- [ ] Price chart shows last 6–12 months
- [ ] Past signal triggers marked with flags/arrows
- [ ] Each marker shows outcome (green = profitable, red = loss)
- [ ] Hovering a marker shows return %

**Priority:** P2 | **Effort:** L

---

## 7. Epic 4 — Decision Engine & Trade Output

### US-401: View Final Trade Recommendation

> **As a** retail investor,  
> **I want** a clear BUY / WATCH / AVOID recommendation,  
> **So that** I know exactly what action to take.

**Acceptance Criteria:**
- [ ] Recommendation is one of: BUY, WATCH, AVOID
- [ ] Confidence score shown (0–100%)
- [ ] Color coding: BUY = green, WATCH = yellow, AVOID = red
- [ ] Decision updates if data refreshes

**Priority:** P0 | **Effort:** S

---

### US-402: View Trade-Ready Output (Entry / Target / Stop-Loss)

> **As a** retail investor,  
> **I want** specific entry price, target price, and stop-loss values,  
> **So that** I can directly execute the trade without guessing.

**Acceptance Criteria:**
- [ ] Entry price shown (near current market price)
- [ ] Target price shown (based on next resistance or avg backtest return)
- [ ] Stop-loss shown (based on support level or -X% from entry)
- [ ] Risk:Reward ratio calculated and displayed (e.g., "1:2.3")
- [ ] Values clearly labeled with ₹ symbol

**Priority:** P0 | **Effort:** M

---

### US-403: Understand Confidence Score

> **As a** retail investor,  
> **I want** to understand what the confidence score means,  
> **So that** I can make an informed decision.

**Acceptance Criteria:**
- [ ] Confidence score breakdown available on hover/click
- [ ] Shows contribution of: signal strength, backtest success rate, sentiment
- [ ] Score range explained (e.g., ">70% = High confidence")
- [ ] Low-confidence explanation warns user appropriately

**Priority:** P1 | **Effort:** S

---

## 8. Epic 5 — Audit Trail & Decision Replay

### US-501: View Past Decisions

> **As a** retail investor,  
> **I want** to see what decisions the system made in the past,  
> **So that** I can evaluate its track record.

**Acceptance Criteria:**
- [ ] "Past Decisions" tab shows last 30 days of recommendations
- [ ] Each entry shows: Stock, Signal, Action, Date, Outcome
- [ ] Outcome calculated at T+5 days
- [ ] Profitable outcomes shown in green, losses in red
- [ ] Overall win rate displayed at the top

**Priority:** P0 | **Effort:** M

---

### US-502: Replay a Past Decision

> **As a** power user,  
> **I want** to replay a past recommendation with full detail,  
> **So that** I can learn from past system behavior.

**Acceptance Criteria:**
- [ ] Clicking a past decision opens full detail view
- [ ] View shows all data as it was at decision time (frozen snapshot)
- [ ] Shows: original signal, reasoning, backtest, action, actual outcome
- [ ] "What happened after?" section shows price chart from decision date onward

**Priority:** P1 | **Effort:** M

---

### US-503: Export Decision Log

> **As a** power user,  
> **I want** to export the decision history to CSV,  
> **So that** I can analyze it in my own tools.

**Acceptance Criteria:**
- [ ] Export button available on Past Decisions screen
- [ ] CSV contains: date, stock, signal, action, confidence, outcome
- [ ] Date range filter before export
- [ ] File named `alphahunter_decisions_YYYY-MM-DD.csv`

**Priority:** P2 | **Effort:** S

---

## 9. Epic 6 — Watchlist & Portfolio

### US-601: Add Stock to Watchlist

> **As a** retail investor,  
> **I want** to add specific stocks to a watchlist,  
> **So that** I get priority alerts for those stocks.

**Acceptance Criteria:**
- [ ] "Add to Watchlist" button on every stock detail page
- [ ] Maximum 20 stocks per watchlist
- [ ] Watchlist persists across sessions
- [ ] Watchlisted stocks are highlighted in scan results

**Priority:** P1 | **Effort:** S

---

### US-602: View Watchlist Status

> **As a** retail investor,  
> **I want** a dedicated watchlist view showing signal status for my stocks,  
> **So that** I can monitor my tracked stocks at a glance.

**Acceptance Criteria:**
- [ ] Watchlist shows all added stocks with last signal and status
- [ ] Stocks with active signals shown at top
- [ ] Last updated timestamp shown per stock
- [ ] Empty state shown if watchlist is empty

**Priority:** P1 | **Effort:** M

---

## 10. Epic 7 — Notifications & Alerts

### US-701: Receive Alert When Signal Triggers

> **As a** retail investor,  
> **I want** to be notified when a high-confidence signal triggers,  
> **So that** I don't miss time-sensitive opportunities.

**Acceptance Criteria:**
- [ ] In-app notification shown within 60 seconds of signal trigger
- [ ] Notification includes: stock name, signal type, confidence %
- [ ] Clicking notification navigates to stock detail
- [ ] Notification badge shown on nav icon
- [ ] User can enable/disable notifications per stock

**Priority:** P1 | **Effort:** M

---

### US-702: Configure Alert Thresholds

> **As a** power user,  
> **I want** to set a minimum confidence threshold for alerts,  
> **So that** I only get notified for high-quality signals.

**Acceptance Criteria:**
- [ ] Slider to set minimum confidence (0–100%)
- [ ] Default threshold: 65%
- [ ] Setting persists across sessions
- [ ] Test notification can be triggered to preview

**Priority:** P2 | **Effort:** S

---

## 11. Epic 8 — Admin & System Monitoring

### US-801: Monitor Data Pipeline Health

> **As an** admin,  
> **I want** to see the status of all data feeds,  
> **So that** I can quickly identify and resolve data issues.

**Acceptance Criteria:**
- [ ] Dashboard shows status per data source: price feed, volume feed, bulk deal feed
- [ ] Last successful fetch timestamp shown per source
- [ ] Red indicator if feed has not updated in > 30 minutes during market hours
- [ ] Manual refresh button per source

**Priority:** P1 | **Effort:** M

---

### US-802: View System Logs

> **As an** admin,  
> **I want** to access system logs filtered by severity,  
> **So that** I can debug issues efficiently.

**Acceptance Criteria:**
- [ ] Logs filterable by: INFO, WARNING, ERROR
- [ ] Logs show: timestamp, module, message
- [ ] Last 1000 log entries retained
- [ ] Export logs as `.log` file

**Priority:** P2 | **Effort:** S

## 13. Definition of Done

A story is "Done" when:
- [ ] All acceptance criteria are met and verified
- [ ] Code reviewed and merged to `main`
- [ ] Unit tests written and passing
- [ ] No P0 bugs open against the story
- [ ] Documented in API contracts if applicable
- [ ] Product owner sign-off received
